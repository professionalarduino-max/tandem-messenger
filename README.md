## ⚡ Коротко

Tandem — полноценный мессенджер без собственного сервера: фронтенд на React общается напрямую
с Supabase, а вся безопасность живёт в Postgres (Row Level Security + функции `security definer`).
Диалоги, группы и каналы, правила чата и премиум-эмодзи — всё решается на стороне базы.
Сообщения, реакции, переименования групп и статусы «печатает…» прилетают по WebSocket, файлы
лежат в приватном бакете со ссылками на час, приложение ставится на телефон как PWA и работает
офлайн-заглушкой при обрыве сети.

| | |
|---|---|
| 🌐 **Демо** | https://professionalarduino-max.github.io/tandem-messenger/ |
| 🧱 **Стек** | React 19 · TypeScript · Vite 8 · Tailwind 4 · Supabase |
| 🔒 **Безопасность** | RLS на каждой таблице и на хранилище, бан, мут, антимат, блокировка по IP и правила чатов на стороне базы, 266 автопроверок прав на живой базе |
| 📦 **Размер** | ~203 КБ gzip, одна страница, без бэкенд-сервера |

## ⏳ Капсула времени — фишка проекта

> Сообщение, которое **физически невозможно** прочитать раньше срока. Такого нет ни в Telegram,
> ни в WhatsApp.

```
┌──────────────────────────────────────────┐
│  ⏳  Капсула времени                     │
│      откроется 25 ноября, 18:30          │
│      осталось 3 дня 4 ч                  │
└──────────────────────────────────────────┘
```

- кнопка ⏳ рядом со скрепкой: текст + срок (через час / завтра / через неделю / через год /
  свой момент) — и капсула уходит в чат;
- в ленте видно только карточку с обратным отсчётом; когда таймер доходит до нуля, текст
  появляется сам, без перезагрузки страницы;
- **главное:** текст лежит не в сообщении, а в отдельной таблице `message_capsules`, и правило
  доступа отдаёт его только при `open_at <= now()`. Ни devtools, ни прямой запрос к API, ни даже
  главный админ не достанут его раньше времени. Автор своё письмо видит всегда — прятать его
  от самого себя бессмысленно;
- удалили сообщение — запечатанный текст стирается триггером вместе с ним;
- в списке чатов и в уведомлении капсула подписана как «Капсула времени» с иконкой песочных
  часов, спойлера нет.

<details>
<summary>Как это устроено в базе</summary>

```sql
create policy capsule_read on public.message_capsules for select using (
  public.can_see_message(message_id)
  and (open_at <= now() or created_by = auth.uid())
);
```

Отправка идёт через `send_capsule()` (`security definer`): проверяет доступ к чату, непустой текст
до 4000 символов и срок от 30 секунд до 5 лет, затем создаёт сообщение вида `capsule` и запечатанную
строку рядом. Проверка `capsule_body_is_sealed` не даёт положить текст капсулы в саму таблицу
сообщений даже случайно.

</details>

## ☰ Панель, каналы и настройки

**Кнопка «три линии»** в левом верхнем углу открывает ящик, как в телеграме: сверху аватарка,
имя и `@юзернейм` (клик — своя карточка профиля), ниже «Новая группа» и «Новый канал», разделы
«Чаты» (со счётчиком непрочитанных), «Группы и каналы», «Люди», «Боты», «Что нового» (с точкой,
пока выпуск не открыт), затем «Настройки», «Админ-панель» (только у главного админа) и «Выйти». Закрывается по Esc, по клику мимо
и сама после выбора пункта — из шапки сайдбара лишние иконки убраны, всё живёт здесь.

**Каналы** — третий тип чата рядом с диалогами и группами (`conversations.type = 'channel'`).
В окне создания переключатель: группа — «говорят все», канал — «пишут админы, читают все».
Канал помечен рупором в списке, в каталоге и в шапке; участники там называются подписчиками,
а вместо поля ввода подписчик видит плашку «В канале пишут только админы — вам остаётся читать
и ставить реакции». Тип чата после создания не меняется: триггер `guard_conversation_update`
отклоняет такую попытку даже у главного админа.

**Настройки группы и канала** — вкладка «Правила» в том же окне, что состав и ссылки:

| Настройка | Что делает |
|---|---|
| Кто может писать | все участники или только админы; у канала закреплено на «только админы» |
| Медленный режим | 10 секунд … 1 час между сообщениями; админов не касается, над полем ввода висит подсказка |
| Показывать в каталоге | снято — чат исчезает из общего списка, но остаётся у своих и по ссылке |
| История видна всем | снято — переписку читают только участники |
| Реакции | выключены — кнопка реакции пропадает, `toggle_reaction()` отвечает отказом |
| Антимат | включён по умолчанию: мат заменяется звёздочками, автору идёт балл; выключается на свой страх и риск |

Все шесть правил проверяются **в базе**, в BEFORE-триггерах `enforce_message_rules`,
`enforce_message_edit_rules` и `enforce_reaction_rules`. Это важно: часть записи идёт через
функции `security definer`, которые RLS не видят, — поэтому запрет живёт в триггере и срабатывает
в любом случае. Менять правила может только админ чата, а `pinned_at` руками не выставить —
закрепление чата у всех осталось рычагом главного админа.

## 😀 Эмодзи и премиум

Кнопка со смайликом слева от поля ввода открывает палитру на **1906 эмодзи** — весь набор
Unicode 16.0 без модификаторов тона кожи, разложенный по девяти вкладкам: Смайлики, Люди,
Природа, Еда, Путешествия, Занятия, Предметы, Символы, Флаги. Поиск работает по русским
названиям из CLDR («улыб», «кот», «флаг Японии»), последние выбранные лежат во вкладке
«Недавние», символ вставляется туда, где стоит курсор, и фокус возвращается в поле.

Набор не тянется из интернета в рантайме: `scripts/build-emoji.mjs` скачивает `emoji-test.txt`
и русские аннотации CLDR, отбирает fully-qualified символы и генерирует `src/lib/emoji.ts`,
который коммитится в репозиторий. В сборке скрипт не участвует.

**Премиум-набор** — 36 эмодзи в четырёх пачках (Праздник, Космос, Золото, Волшебство),
вкладка с короной. Он открыт не всем:

| Кому открыт | Почему |
|---|---|
| Главному админу | всегда |
| Админу любой группы или канала | за роль |
| Всем, кто писал за последние **14 дней** | за активность |

Остальные видят пачки, но на попытке отправить получают отказ — и в сообщении, и в реакции,
и в правке старого сообщения. Решает одна функция `can_use_premium()`, её же результат
показывает панель: «Премиум открыт: вы админ группы или канала» или «Напишите что-нибудь —
и набор откроется». Окно скользящее: перестал писать на две недели — набор закрывается сам,
это проверяется в `smoke.mjs` сдвигом дат старых сообщений.

## 🪪 Карточка профиля, модерация и приглашения

**Клик по любой аватарке** — в ленте, в каталоге людей, в составе группы, в админ-панели — открывает
карточку человека: аватарка с зелёной точкой «в сети», имя, `@юзернейм` (клик копирует), когда был
последний раз, «о себе», три счётчика (сообщения, собранные реакции, группы), дата регистрации,
общие группы и кнопка **«Написать»** — диалог создаётся на лету, если его ещё не было.
Карточку отдаёт одна функция `user_card(id)`: считает всё сама и показывает почту **только** главному
админу. На свою карточку вместо «Написать» приходит «Редактировать профиль».

**Инструменты главного админа** — в той же карточке, раздел «Действия админа»:

| Рычаг | Что делает | Функция |
|---|---|---|
| Заблокировать | закрывает запись везде и сам вход (`auth.users.banned_until`), с причиной | `admin_set_ban(id, on, reason)` |
| Мут на 15 минут / час / сутки / неделю | читать можно, писать и ставить реакции — нет | `admin_set_mute(id, minutes, reason)` |
| Сделать админом / снять | флаг главного админа | `admin_set_super(id, on)` |
| Стереть сообщения | мягко удаляет все сообщения человека разом | `admin_purge_user_messages(id)` |

Запрет живёт **в базе, а не в кнопках**: политики `messages_insert` и `reactions_insert` спрашивают
`can_write()`, а функции `security definer` (`toggle_reaction`, `send_capsule`, `join_group`,
`create_group`, `create_direct_conversation`) проверяют мут и бан внутри себя — они пишут в обход RLS,
поэтому полагаться на политики там нельзя. Из консоли браузера запрет не обойти: сервер ответит
«Сейчас вам нельзя отправлять сообщения». Интерфейс только объясняет причину — вместо поля ввода
красная плашка при бане и янтарная «Режим тишины ещё …» при муте. Свои права админ не трогает:
в собственной карточке раздела модерации нет.

**Пригласительные ссылки** — вкладка «Ссылки» в настройках группы. Админ выбирает срок (сутки,
неделя, месяц, бессрочно) и лимит (1, 5, 25 человек или без лимита), получает адрес вида
`…/i/3srrnnj4` и сразу в буфере обмена. Код из 8 символов без похожих букв (`l`, `1`, `o`, `0`);
у каждой ссылки видно состояние — живая, отозвана, просрочена, исчерпана.

Страница приглашения открывается **до входа**: `invite_info(code)` — единственная функция,
доступная анониму, и она показывает только название группы, описание, аватарку и число участников.
Кто не вошёл — видит «Войти и вступить» и форму входа прямо на этой же странице, после входа адрес
остаётся прежним и остаётся нажать «Вступить в группу». `redeem_invite(code)` ещё раз проверяет срок,
лимит и бан, добавляет в группу и увеличивает счётчик переходов.

**@упоминания.** Юзернеймы везде показываются с собакой, а в настройках «@» нарисована слева от поля
и не стирается. В поле ввода «@» открывает подсказку (`mention_candidates`): участники этого чата
первыми, стрелки и Enter выбирают, Esc закрывает. В тексте сообщения `@имя` становится кнопкой —
клик открывает карточку, своё упоминание подсвечивается золотым, у сообщения появляется золотая
полоска слева, а уведомление в браузере подписано «· вас упомянули». Ссылки в тексте тоже становятся
кликабельными. В юзернеймах допустимы эмодзи, поэтому `@⭐⭐⭐⭐⭐` подставляется и подсвечивается
наравне с латиницей.

## 🧹 Антимат и блокировка по IP

### Антимат

Фильтр **не отклоняет** сообщение, а чистит его: мат заменяется на `***`, сообщение уходит в чат,
а автору начисляется балл. Так сделано намеренно — отказ откатил бы транзакцию вместе со счётчиком,
и наказание никогда бы не наступило.

| Баллов | Что происходит | Причина в карточке |
|---|---|---|
| 3 | час тишины | `Автомут: мат` |
| 6 | сутки тишины | `Автомут: мат` |
| 9 | блокировка аккаунта и входа | `Автоблокировка: мат` |

Мягкое слово стоит балл, грубое — два. Баллы обнуляются кнопкой в карточке человека, общее число
срабатываний остаётся в истории.

Перед сверкой текст нормализуется: регистр, подмены букв (`@ $ 0 3 4 6` и латинские `a c e o p x y k b h m t`)
и `ё` сводятся к кириллице, всё остальное становится пробелом. Поэтому ловится и `хуууй`,
и `х у й`, и `мvдак`. Каждое слово словаря хранится как регулярка с `+` после каждой буквы,
а не как строка, — растянутые буквы и раздельное написание покрываются одним выражением.

Ложные срабатывания отсекаются точными классами и ретроспективой: `(?<![рл])е+б+а+[тлнш]+`
пропускает «погребать», «требовать», «хлебать» и «колебать», `х+е+р+[нюяов]+` — «херувима»,
`с+у+ч+[кар]+` — «сучок». Это проверяется в `smoke.mjs` отдельной строкой из восьми приличных слов.

Фильтр работает не только в сообщениях: названия и описания групп и каналов, юзернейм, имя
и «о себе» в профиле с матом **просто не сохраняются** (триггеры `conversations_words` и `profiles_words`),
а текст капсулы времени чистится при отправке. Главного админа фильтр не трогает,
в настройках любой группы его можно выключить, а словарь (35 слов из коробки) редактируется
в админ-панели: своё слово добавляется с выбором «грубое» и «целиком».

> **Честно о границах.** Словарь не знает транслита: «pizdec» латиницей пройдёт. Полную
> транслитерацию сознательно не делали — тогда английское «hero» превращалось бы в мат.
> Фильтр ловит типичную подмену символов, а не любую фантазию.

### Блокировка по IP

Каждый вызов `touch_last_seen()` (приложение шлёт его при входе и раз в минуту) записывает адрес
в `user_ips`: первый визит, последний, число заходов. Адрес берётся из заголовка PostgREST, клиент
его не передаёт и подделать не может. В карточке человека главный админ видит список адресов,
сколько раз с него заходили и **сколько ещё аккаунтов сидит с того же адреса**.

| Кнопка | Что делает |
|---|---|
| «забанить» у строки | закрывает один адрес (`admin_ban_ip`) |
| «забанить все» | закрывает все адреса человека (`admin_ban_user_ips`) |
| панель «Блокировки по IP» | ручной ввод адреса **или подсети** — `203.0.113.0/24` закрывает 256 адресов разом |

Адрес хранится типом `inet`, проверка идёт оператором `<<=`, поэтому одна строка покрывает
и адрес, и сеть. С закрытого адреса нельзя писать, вступать в группы и создавать чаты —
проверка `is_ip_banned()` стоит в тех же триггерах, что бан и мут, так что новый аккаунт
не поможет.

Три предохранителя от самострела: нельзя закрыть **свой** адрес, нельзя закрыть адрес,
с которого заходит главный админ, и «забанить все» молча пропускает такие адреса
(возвращает число реально закрытых).

> **Честно о границах.** IP — грубый инструмент. За одним адресом мобильного оператора сидят
> тысячи людей, в офисе и общежитии — весь дом, а VPN меняется за секунду. Блокировка по IP
> тут вспомогательная мера против одного настырного человека, а не защита: сначала бан аккаунта,
> IP — только если он возвращается. Список «кто ещё сидит с этого адреса» показан рядом с кнопкой
> именно для этого.

## 🤖 Боты на блоках

Бот в Tandem — не скрипт на сервере, а **проект на блоках**, который школьник собирает мышкой
в [TurboWarp](https://turbowarp.org) или [DashBlocks](https://dashblocks.org) (это форк Scratch
из той же семьи, что PenguinMod: те же блоки, свой формат `.dbp` — внутри обычный zip, как `.sb3`,
и та же система расширений, что у TurboWarp). Страница `/bots` заводит бота, а расширение
`bot-extension.js` даёт проекту 39 блоков для переписки.

### Как это выглядит

1. **Создать бота** на странице «Боты»: название, описание, аватарка. Имя латиницей — если
   не кончается на `bot`, дописывается само (`weather` → `@weatherbot`). Пять ботов на хозяина,
   пятьдесят у главного админа.
2. **Добавить в чат** — выпадашкой прямо в карточке бота; список берётся из чатов, где вы админ.
3. **Загрузить расширение** в TurboWarp или DashBlocks: «Расширения» → «Загрузить по ссылке» →
   `https://professionalarduino-max.github.io/tandem-messenger/bot-extension.js`.
4. **Вставить токен** в блок «подключить бота по токену» и нажать зелёный флаг.
5. **Приложить проект** (`.sb3` или `.dbp`, до 10 МБ) к боту — чтобы файл не потерялся и его
   можно было скачать с любого компьютера.

Минимальный эхо-бот целиком:

```
когда щёлкнут по флагу
  подключить бота по токену (tdm_…)

когда боту написали
  отправить в (чат сообщения) текст (соединить «ты написал: » (текст сообщения))
```

### Блоки

| Группа | Блоки |
|---|---|
| Подключение | подключить бота по токену · бот подключён? · имя бота · @имя бота · переименовать · изменить описание · отключить |
| Сообщения | отправить в чат · ответить на сообщение · процитировать · изменить своё · удалить своё · поставить реакцию · закрепить своё (нужна админка в чате) · id моего сообщения |
| События | **когда боту написали** · **когда написали [слово]** · **когда бота позвали** · ждать сообщение · текст · автор · имя автора · чат · это личка? · в тексте есть [слово]? |
| Чаты и люди | список чатов · кто в чате · свойство человека (имя, @имя, описание, онлайн, сообщений, бот?) · история чата · войти по приглашению · выйти из чата |
| Память | запомнить · вспомнить · забыть · что бот помнит |
| Служебные | записать заметку · последняя ошибка · элемент списка · длина списка |

«Когда…» — настоящие шляпы: расширение раз в 1.2 секунды спрашивает базу о новых сообщениях,
складывает их в очередь и выдаёт по одному, так что каждая шляпа видит каждое сообщение ровно раз.

### Что внутри

У бота есть обычная строка в `profiles` (с флагом `is_bot`), но нет учётной записи в `auth.users` —
поэтому внешний ключ на `auth.users` заменён на триггер, который убирает профиль вслед за удалённым
человеком. Все действия бота идут через функции `bot_*(token_in, …)` с `security definer`, выданные
роли `anon`: расширение знает только токен и публичный ключ проекта, а база сама проверяет, кто это
и куда ему можно. Поэтому бот не обходит ни один запрет — его сообщения проходят те же триггеры,
что и человеческие: бан, мут, антимат, медленный режим, правила канала, блокировка по IP.

Токен выглядит как `tdm_…`, хранится в таблице `bots` (её видит только хозяин — RLS), показывается
по кнопке и меняется одним нажатием. Лимит — 240 действий в минуту на бота. Выключить бота может
хозяин переключателем, а главный админ — любого бота из раздела «Боты» в админ-панели.

> **Честно о границах.** Проект живёт во вкладке: закрыли TurboWarp — бот замолчал. Это не
> серверный бот с аптаймом, а «пока открыто — работает», как любой проект на Scratch. Новости
> бот узнаёт опросом раз в 1.2 секунды, а не мгновенным пушем. Токен лежит прямо внутри проекта,
> поэтому выложенный в общий доступ `.sb3` = отданный бот (на этот случай и есть кнопка «Сменить»).
> Расширение грузится по ссылке, а значит работает в песочнице: доступа к потрохам проекта у него
> нет, только сеть. И умеет бот ровно то, что в таблице выше: текст, реакции, закрепления, память —
> ни файлов, ни голосовых, ни создания групп, ни модерации. Закрепление — по тем же правилам, что
> и у людей: сначала выдайте боту админку в настройках чата, во вкладке «Участники» (бот там
> помечен значком), иначе блок честно ответит «закреплять может только админ чата».

## 📌 Главный чат и закреплённые чаты

**«Общий чат» — главный:** он всегда первый в списке, помечен золотой кнопкой и в него автоматически
попадает каждый новый человек (триггер `handle_new_user`). Покинуть его нельзя — `leave_group()`
отвечает отказом, а снять с него закрепление не может даже главный админ.

**Закрепление у всех** — кнопка в шапке чата, видна только главному админу (`admin_pin_conversation`).
Закреплённая группа поднимается сразу под главным чатом **у всех** и помечается синей кнопкой;
заодно все профили добавляются в её состав, иначе закреплённый чат остался бы невидимым для тех,
кто в нём не состоит. Порядок списка жёсткий: главный чат → закреплённые → остальные по свежести.
Сводка «Модерация и закрепления» в админ-панели показывает, кто забанен, кто в муте и что закреплено,
и позволяет снять любое из этих состояний одной кнопкой.

## 👥 Каталог людей и админ-панель

**Вкладка «Каталог»** собирает все открытые группы и каналы разом: видно тип значком, число
участников или подписчиков, замок у тех, кого хозяин убрал из каталога, и кнопка «войти»
или «подписаться».

**Вкладка «Люди»** — это не поиск по подстроке, а полный список всех, кто пользуется мессенджером.
Первыми идут те, кто сейчас в сети, у каждого видно имя, `@юзернейм`, время последнего визита,
число сообщений, метка главного админа и значок бана или мута. Клик по строке открывает личный чат
(а на себе — настройки), клик по аватарке — карточку профиля.
Данные отдаёт функция `list_users(q)`, поиск по тому же списку работает по имени и юзернейму.

**Админ-панель** (`/admin`, иконка графика в шапке) видна только главному админу и собирает
живую сводку по всему сервису:

| Блок | Что показывает |
|---|---|
| Главные цифры | пользователи и кто в сети, сообщения за сегодня, чаты (диалоги, группы, каналы), объём вложений |
| График за 14 дней | сколько сообщений писали каждый день |
| Модерация и закрепления | кто забанен, кто в муте и до какого часа, какие чаты закреплены у всех — всё снимается одной кнопкой |
| Люди | всего, онлайн, заходили за сутки и за неделю, новые за неделю |
| Что пишут | текст, файлы, голосовые, капсулы, реакции, закреплённые, правки, удаления |
| Капсулы времени | сколько запечатано, сколько уже открыто, ближайшее вскрытие |
| Премиум-эмодзи | сколько символов в пачках и скольким людям сейчас открыт набор |
| Блокировки по IP | закрытые адреса и подсети, кто с них заходил, ручной ввод нового адреса, снятие одной кнопкой |
| Антимат | срабатывания всего и за сегодня, сколько сейчас в автомуте и автобане, топ нарушителей с обнулением баллов, словарь с добавлением и удалением слов |
| Боты | сколько ботов завели, сколько сейчас на связи, сколько сообщений они отправили; у каждого хозяин, движок, файл проекта и кнопка «Выключить» |
| Самые активные | топ-8 людей с полоской активности |
| Живые группы и каналы | топ-6 чатов по сообщениям, клик ведёт внутрь |
| Новые пользователи | пятеро последних, кто зарегистрировался |

Цифры считает сама база: одна функция `admin_stats()` возвращает готовый JSON и начинается
с проверки `is_super(auth.uid())` — без прав она отвечает ошибкой, а не пустым объектом.
Клиент ничего не агрегирует и не обходит RLS; панель обновляется раз в минуту и по кнопке.

## 🔐 Права доступа

| Кто | Что может |
|---|---|
| Любой вошедший | видит **все группы и каналы** в каталоге и **всех людей** во вкладке «Люди», читает, вступает одним кликом, пишет, реагирует |
| Подписчик канала | читает и ставит реакции; писать может только админ |
| Участник личного чата | только свой диалог; посторонние не читают, не пишут, не реагируют, не скачивают вложения |
| Админ группы или канала | состав, роли, название, описание, аватарка, **правила чата**, закреплённые, удаление сообщений и чата, **пригласительные ссылки**, **премиум-эмодзи** |
| **Главный админ** | админ **в каждой** группе и канале автоматически, включая чужие и будущие; модерация везде; **бан, мут, права, очистка сообщений, закрепление чата у всех**; **админ-панель со статистикой** |
| В муте | читает всё, но не пишет и не ставит реакции — пока не истечёт срок; на трёх баллах за мат мут ставится сам |
| В бане | не пишет, не реагирует, не вступает в группы и не создаёт чаты; по приглашению тоже не пройдёт |
| С закрытого IP | не пишет ниоткуда и ни с какого аккаунта — адрес проверяется в тех же триггерах, что бан и мут |
| Бот | только то, что разрешает токен: пишет в чаты, куда его добавил админ, и в личку; под теми же банами, мутами, антиматом и правилами чата; чужие сообщения не правит, людей не модерирует |
| Хозяин бота | заводит до пяти ботов, видит и меняет их токены, выключает и удаляет; чужого бота не трогает — `bot_guard()` отвечает «Это чужой бот» |

Главный админ определяется по почте в функции `super_admin_email()` и флагу `profiles.is_super_admin`.
Триггеры `setup_new_conversation` и `sync_super_admin` держат это состояние в актуальном виде:
создаётся новая группа — главный админ уже в ней с ролью `admin`.

Хранилище защищено теми же правилами: путь `avatars/users/{id}` пишет только владелец,
`avatars/groups/{id}` — админ группы, `avatars/bots/{id}` и `botcode/{id}` — хозяин бота,
`attachments/{conversation_id}` — участник чата (для открытых групп — любой вошедший).

## 🚀 Деплой

Проект собирается в статику, поэтому подходит любой хостинг фронтенда.

### GitHub Pages (используется сейчас)

Всё уже настроено: пуш в `main` запускает `.github/workflows/pages.yml`, который собирает проект
с `BASE_PATH=/tandem-messenger/`, кладёт копию `index.html` в `404.html` (SPA-маршруты вроде
`/c/<id>` иначе давали бы 404) и публикует `dist/`.

Чтобы развернуть у себя:

1. **Settings → Pages → Source: GitHub Actions**;
2. при другом имени репозитория поправить `BASE_PATH` в `pages.yml` (для `user.github.io` — `/`);
3. ключи проекта — **Settings → Secrets and variables → Actions → Variables**:
   `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

### Vercel

```bash
npm i -g vercel
vercel link        # выбрать аккаунт и проект
vercel --prod      # сборка и выкладка
```

`vercel.json` уже содержит сборку (`npm run build` → `dist`), SPA-перенаправление на `index.html`
и заголовки кеширования: service worker не кешируется, хешированная статика — на год.

### Переменные окружения

| Имя | Значение |
|---|---|
| `VITE_SUPABASE_URL` | `https://<ваш-проект>.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | публичный anon-ключ |
| `BASE_PATH` | только для Pages: подпапка сайта, например `/tandem-messenger/` |

Если переменные не заданы, приложение возьмёт публичные значения по умолчанию из
`src/lib/supabase.ts`. Секретный `service_role` в деплой не попадает — он нужен только скриптам
в `scripts/`.

После первого деплоя добавьте адрес сайта в **Supabase → Authentication → URL Configuration**
(Site URL и Redirect URLs), иначе письма подтверждения будут вести на `localhost`.

## ✅ Проверки

```bash
# права доступа на живой базе: 266 проверок, 6 реальных аккаунтов
SUPABASE_SERVICE_KEY=... ADMIN_PASSWORD=... node scripts/smoke.mjs

# интерфейс в браузере: вход → каталог → отправка сообщения
TEST_PASSWORD=... node scripts/ui-check.mjs

# панель, каналы, настройки, эмодзи, карточки, модерация, ссылки, антимат, боты: 61 проверка
TEST_PASSWORD=... node scripts/admin-check.mjs

# само расширение в настоящем браузере: все 39 блоков по очереди, 63 проверки
SUPABASE_SERVICE_KEY=... node scripts/bot-blocks-check.mjs

# опубликованная версия: базовый путь, service worker, манифест, прямые ссылки
node scripts/pages-check.mjs [адрес]

# пересобрать набор эмодзи из Unicode и CLDR (результат коммитится)
node scripts/build-emoji.mjs
```

Последняя проверка на боевом адресе — 11 из 11: страница открывается, вход отрисован, ассеты
и манифест ведут в подпапку, service worker зарегистрирован на `/tandem-messenger/`, Supabase
отвечает с этого домена, прямая ссылка на чат поднимает приложение, консоль чистая.

`smoke.mjs` проходит по всем правилам доступа: чужие чаты и вложения, капсулы времени, права
админа группы и главного админа, карточки профиля, бан и мут (включая попытку обойти их реакцией
или правкой старого сообщения), пригласительные ссылки со всеми состояниями, главный чат
и закрепления, каналы (подписчик читает и реагирует, но не пишет; тип чата не подменить),
все шесть правил группы — кто пишет, медленный режим, каталог, история, реакции, антимат —
и премиум-эмодзи вместе с закрытием 14-дневного окна. Отдельные разделы проверяют антимат
(замазывание, ложные срабатывания на приличных словах, баллы, автомут на третьем балле, словарь,
выключение фильтра в группе) и блокировку по IP (запись адресов, отказ закрыть свой адрес и адрес
главного админа, бан подсети, снятие). Три раздела про ботов проходят весь путь: создание с чисткой имени, чужой токен и чужая
папка в хранилище, затем всё токен-API по публичному ключу — отправка, правка, реакция, события
(одно сообщение не приходит дважды), история, участники, память, заметка, смена токена, —
и напоследок выключение ботом-хозяином и главным админом, удаление из чата и удаление самого бота
вместе с профилем. В конце — что анониму не отвечает ни одна функция, кроме `invite_info`.
Он сам за собой убирает: тестовые группы, диалоги, файлы, аккаунты и тестовые IP-блокировки
удаляются в конце.

`bot-blocks-check.mjs` проверяет не базу, а сам файл расширения. Он поднимает Chromium, подсовывает
расширению заглушку вместо редактора Scratch и дёргает блоки ровно так, как это делает движок:
у каждого из 39 блоков есть подпись и код, шляпы объявлены не «по фронту», подключение, отправка
по названию чата, правка, закрепление (без админки в чате — отказ с понятной причиной, с админкой —
закрепляет), ответ и цитата, реакция, список чатов и участников, история, память, заметка хозяину,
переименование, списки через запятую, JSON и перевод строки, удаление своего сообщения и выход
из чата. Сообщение боту приходит через настоящий опрос базы — скрипт ждёт его блоком «ждать
сообщение» и проверяет, что каждая шляпа срабатывает ровно один раз, а после «отключить бота»
опрос прекращается. Бот, чат и хозяин создаются на живой базе и удаляются в конце.

`ui-check.mjs`, `admin-check.mjs` и `bot-blocks-check.mjs` требуют системных библиотек Chromium
(`npx playwright install --with-deps chromium`).

Ключи: в репозитории и в коде лежит только публичный ключ. `service_role` и пароли передаются
через переменные окружения.

`bonus_time_capsule` → `directory_and_admin_stats` → `preview_kind_for_icons` →
`moderation_ban_mute` → `invite_links` → `home_chat_and_global_pins` →
`profile_cards_and_moderation_lists` → `lock_down_function_grants` → `mentions_support` →
`mute_covers_definer_functions` → `channel_conversation_type` → `channels_and_group_settings` →
`channel_aware_functions` → `channels_in_stats_and_cards` → `premium_emoji` →
`ip_tracking_and_bans` → `profanity_filter_and_auto_ban` → `profanity_hooks_and_admin` →

| Миграция | Что добавляет |
|---|---|
| `init_messenger`, `rpc_functions` | профили, чаты, участники, сообщения, RLS, главный админ |
| `part2_*` | аватарки и бакеты, вложения, ответы, редактирование, полнотекстовый поиск |
| `part3_reactions_pins_voice` | `message_reactions`, `toggle_reaction()`, `pin_message()`, `can_see_message()`, `duration_ms`, закрепы |
| `bonus_time_capsule` | вид сообщения `capsule`, `messages.open_at`, таблица `message_capsules`, `send_capsule()`, триггер `capsule_cleanup` |
| `directory_and_admin_stats` | `list_users(q)` — весь каталог людей, `admin_stats()` — сводка для главного админа, превью чатов без эмодзи |
| `preview_kind_for_icons` | `list_conversations()` отдаёт `last_message_kind`, чтобы список чатов рисовал иконку типа сообщения |
| `moderation_ban_mute` | `profiles.banned_at`, `muted_until` и причины, `is_banned()`, `is_muted()`, `can_write()` в политиках записи, `admin_set_ban()`, `admin_set_mute()`, `admin_set_super()`, `admin_purge_user_messages()` |
| `invite_links` | таблица `invites` с кодом из 8 символов, `create_invite()`, `list_invites()`, `revoke_invite()`, `redeem_invite()` и `invite_info()` — единственная функция для анонима |
| `home_chat_and_global_pins` | `conversations.is_home` и `pinned_at`, «Общий чат» как главный, автоматическое вступление новичков, `admin_pin_conversation()`, запрет покидать главный чат, порядок списка чатов |
| `profile_cards_and_moderation_lists` | `user_card(id)` — карточка со статистикой, общими группами и почтой для админа, `admin_moderation()` — сводка по банам, мутам и закреплениям |
| `lock_down_function_grants` | снимает выданное Postgres по умолчанию право `execute` у `public` и `anon` со **всех** функций схемы и возвращает его только `authenticated` |
| `mentions_support` | `user_card_by_name(name)` и `mention_candidates(conv, q)` — подсказка @упоминаний, участники чата первыми |

| `channel_conversation_type` | третий тип чата `channel`, `is_public_conv()` для «группа или канал», `is_group()` остаётся строгим — старые правила не меняют смысл |
| `channels_and_group_settings` | `conversations.posting`, `slow_mode_seconds`, `listed`, `history_visible`, `reactions_enabled`; триггеры `enforce_message_rules`, `enforce_message_edit_rules`, `enforce_reaction_rules` — правила работают и для `security definer`-функций; `guard_conversation_update()` не даёт менять тип чата и выставлять `pinned_at` мимо главного админа |
| `channel_aware_functions` | `create_conversation(title, description, type)` вместо `create_group()`, каналу сразу ставится «пишут админы»; каталог, список чатов, вступление и настройки понимают каналы |
| `channels_in_stats_and_cards` | каналы считаются отдельно в `admin_stats()` и в карточке профиля, в топе — «живые группы и каналы» |
| `premium_emoji` | таблица `premium_emoji` (4 пачки, 36 символов), `can_use_premium()` — админ или сообщение за последние 14 дней, `premium_status()` для интерфейса, `premium_emoji_in(text)`; запрет вшит в те же триггеры сообщений, правок и реакций |
| `ip_tracking_and_bans` | `client_ip()` из заголовков PostgREST, таблицы `user_ips` и `ip_bans` (тип `inet`, проверка оператором `<<=`), запись адреса в `touch_last_seen()`, `is_ip_banned()`, `admin_user_ips()`, `admin_ban_ip()`, `admin_unban_ip()`, `admin_ban_user_ips()`, `admin_ip_bans()` с защитой своего адреса и адреса главного админа |
| `profanity_filter_and_auto_ban` | `conversations.profanity_filter`, словарь `bad_words` (35 слов регулярками), `norm_text()` и `word_pattern()`, `profanity_hit()`, `censor()`, счётчики `profanity_strikes` и журнал `profanity_log`, `register_profanity()` — час тишины на 3 баллах, сутки на 6, блокировка на 9 |

| `ip_ban_display` | одиночный адрес показывается без `/32`, подсеть — с маской |
| `bots_platform` | `profiles.is_bot`, таблицы `bots` и `bot_storage`, бакет `botcode` для `.sb3` и `.dbp`; внешний ключ `profiles → auth.users` заменён триггером, иначе профилю бота негде жить |
| `bots_owner_api` | `create_bot()`, `my_bots()`, `update_bot()`, `set_bot_code()`, `rotate_bot_token()`, `delete_bot()`, `add_bot_to_chat()`, `remove_bot_from_chat()` — всё только для хозяина и главного админа |
| `bots_token_api` | `bot_auth(token)` с лимитом 240 действий в минуту, `bot_connect()`, `bot_me()`, `bot_send()`, `bot_edit()`, `bot_delete()`, `bot_react()`, `bot_pin()` — выданы роли `anon`, потому что расширение знает только токен |

## 🩹 Что починено в бонусной части

| Было | Стало |
|---|---|
| ответ на голосовое/удалённое сообщение цитировался как «вложение» | цитата знает про тип: «Голосовое», «Капсула времени», «сообщение удалено» — с иконкой |
| `URL.createObjectURL` вызывался прямо в рендере — утечка памяти на каждый кадр | ссылка живёт в хуке и освобождается при смене файла |
| удаление сообщения не показывалось до ответа сервера, а при ошибке молчало | оптимистичное удаление с откатом и текстом ошибки |
| ошибка одного чата оставалась на экране при переходе в другой | состояние ошибки сбрасывается при смене чата |
| уход со страницы во время записи оставлял микрофон включённым | запись останавливается при размонтировании |
| `MediaRecorder` мог не ответить, и кнопка «Отправить» зависала | сторож на 2 с, обработка `onerror`, пустая запись отбрасывается |
| удалённые файлы оставались в бакете навсегда | файл стирается вместе с сообщением, при удалении группы — вся её папка |
| расширение файла из имени попадало в путь как есть | `safeExt()`: только латиница и цифры, максимум 12 символов |
| `onAuthStateChange` мог заблокировать клиент Supabase | профиль грузится отложенно, повторное событие с тем же id игнорируется |
| пачка сообщений дёргала список чатов по разу на каждое | события склеиваются, один запрос на 200 мс |
| множество показанных уведомлений росло без предела | список id ограничен 400 записями |
| переименование группы и исключение участника не доходили до собеседника | подписка на `conversations` и `conversation_members`; если чат исчез — возврат к списку |
| реакция падала без следа в консоль | ошибка показывается в чате |
| Postgres по умолчанию раздаёт `execute` роли `public`, поэтому **все** RPC проекта отвечали и анониму | права сняты со всех функций схемы и возвращены только `authenticated`; анониму оставлена одна `invite_info` — проверяется отдельным разделом в `smoke.mjs` |
| мут не работал там, где запись идёт через `security definer` — реакцию можно было поставить и в тишине | мут и бан проверяются внутри самих функций, политики там бессильны |
