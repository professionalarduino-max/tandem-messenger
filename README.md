# Tandem — части 1, 2, 3 + бонус

Веб-мессенджер на React + Supabase. Закрывает недели 0–4 общего плана плюс то, что вы просили
отдельно: **открытый каталог групп** и **главного админа над всем продуктом**.

## Что умеет

### Часть 1 — основа
- регистрация и вход по почте и паролю
- три вкладки в сайдбаре: **Чаты** (мои), **Группы** (все группы всех пользователей), **Люди** (поиск)
- личные чаты 1:1 и групповые
- сообщения в реальном времени, оптимистичная отправка, непрочитанные, разделители по дням
- мягкое удаление сообщений (своих — всегда, чужих — админам)
- управление группой: состав, назначение и снятие админов, исключение, удаление группы
- адаптив: на телефоне сайдбар и чат — отдельные экраны

### Часть 2 — профили, группы, вложения
- **аватарки**: загрузка файла для профиля и для группы, автосжатие в webp 512×512 на клиенте,
  публичный бакет `avatars`, удаление своей аватарки
- **профиль**: имя, юзернейм, «о себе» (до 280 символов); чужой профиль открывается из шапки
  личного чата карточкой с био и статусом
- **настройки группы** в отдельном окне: название, описание, аватарка, вкладка участников —
  добавление по поиску, повышение и снятие админов, исключение, выход, удаление группы
- **вложения**: кнопка 📎, перетаскивание файла в окно чата и вставка из буфера; картинки
  показываются превью и открываются во весь экран, файлы — карточкой со скачиванием.
  Приватный бакет `attachments`, ссылки подписываются на час. Лимит 20 МБ
- **ответы на сообщения**: цитата в пузыре, клик по цитате прокручивает к оригиналу
  (при необходимости догружает историю)
- **редактирование своих сообщений** прямо в пузыре, пометка «изменено»
- **«печатает…»** через Realtime Broadcast — в базу ничего не пишется
- **поиск по чату**: полнотекстовый, русская морфология (`tsvector` + GIN), переход к найденному
- подгрузка истории: лента грузится страницами по 50 при прокрутке вверх

### Часть 3 — голос, реакции, закрепы, уведомления, PWA
- **голосовые сообщения**: кнопка 🎤 появляется вместо «отправить», когда поле пустое; во время
  записи — таймер, «Отмена» и «Отправить». Запись идёт через `MediaRecorder` (opus/webm, на iPhone —
  mp4), файл уходит в тот же приватный бакет `attachments`. В пузыре — свой проигрыватель с
  волной, временем и перемоткой; записи короче 0,7 с не отправляются
- **реакции**: кнопка 🙂 у каждого сообщения, 8 эмодзи, повторное нажатие снимает свою реакцию.
  Счётчики группируются по эмодзи, своя реакция подсвечена. Прилетают в реальном времени
  (отдельная таблица `message_reactions` в публикации Realtime)
- **закреплённые сообщения**: панель над лентой, несколько закрепов листаются стрелкой, клик —
  прыжок к сообщению. В группе закрепляет админ (и ABDev), в личном чате — любой участник
- **уведомления**: всплывающее окно браузера, когда вкладка свёрнута или открыт другой чат,
  и счётчик непрочитанных в заголовке вкладки. Включается в настройках, там же тестовое
  уведомление; выключатель хранится локально
- **PWA**: манифест, иконки (включая maskable), service worker. Оболочка и статика кешируются,
  данные всегда идут в сеть, при обрыве — страница «Нет подключения». Приложение ставится
  на телефон и на компьютер; кнопка «Установить» — в настройках

### Бонус — «Капсула времени» ⏳
Уникальная штука, которой нет ни в Telegram, ни в WhatsApp: сообщение, которое **нельзя
прочитать раньше срока**.

- кнопка ⏳ рядом со скрепкой: текст, срок (через час / завтра / через неделю / через год /
  свой момент) — и капсула уходит в чат
- в ленте видно только карточку с обратным отсчётом: «Капсула времени · 3 дня 4 ч ·
  откроется 25 ноября, 18:30». Когда таймер доходит до нуля, текст появляется сам, без перезагрузки
- главное: **текст физически лежит не в сообщении**, а в отдельной таблице `message_capsules`,
  и правило доступа отдаёт его только при `open_at <= now()`. Подсмотреть через devtools,
  через API или прямым запросом к базе нельзя — даже главному админу. Автор своё письмо видит
  всегда (прятать его от самого себя бессмысленно)
- удалили сообщение — запечатанный текст стирается вместе с ним
- в списке чатов и в уведомлении капсула подписана как «⏳ Капсула времени», так что спойлера нет

## Правила доступа

| Кто | Что может |
|---|---|
| Любой вошедший | видит **все группы** в каталоге, читает их, вступает одним кликом, пишет, реагирует |
| Участник личного чата | только свой диалог; посторонние не читают, не пишут, не реагируют, не скачивают вложения |
| Админ группы | состав, роли, название, описание, аватарка, закреплённые, удаление сообщений и группы |
| **Главный админ (ABDev)** | админ **в каждой** группе автоматически, включая чужие и будущие; модерация везде |

Главный админ определяется по почте в функции `super_admin_email()` и флагу `profiles.is_super_admin`.
Триггеры `setup_new_conversation` и `sync_super_admin` держат это состояние в актуальном виде:
создаётся новая группа — главный админ уже в ней с ролью `admin`.

Хранилище защищено теми же правилами: путь `avatars/users/{id}` пишет только владелец,
`avatars/groups/{id}` — админ группы, `attachments/{conversation_id}` — участник чата
(для открытых групп — любой вошедший).

## Запуск

```bash
npm install
cp .env.example .env.local   # вписать URL и публичный ключ
npm run dev                  # дев-сервер, порт 5173
```

Service worker в дев-режиме намеренно отключён (мешал бы горячей перезагрузке). Чтобы проверить
установку приложения и офлайн-режим, нужна собранная версия:

```bash
npm run build
npm run preview              # порт 4173, здесь работает PWA
```

## Деплой

Проект собирается в статику, поэтому подходит любой хостинг фронтенда. Настроен Vercel:

```bash
npm i -g vercel
vercel link        # выбрать аккаунт и проект
vercel --prod      # сборка и выкладка
```

`vercel.json` уже содержит сборку (`npm run build` → `dist`), SPA-перенаправление на
`index.html` (иначе прямая ссылка на `/c/<id>` давала бы 404) и заголовки кеширования:
service worker не кешируется, хешированная статика — на год.

Переменные окружения в настройках проекта Vercel (вкладка Environment Variables):

| Имя | Значение |
|---|---|
| `VITE_SUPABASE_URL` | `https://<ваш-проект>.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | публичный anon-ключ |

Если их не задать, приложение возьмёт те же публичные значения из `src/lib/supabase.ts`.
Секретный `service_role` в деплой не попадает — он нужен только скриптам в `scripts/`.

После первого деплоя добавьте адрес сайта в Supabase → Authentication → URL Configuration
(Site URL и Redirect URLs), иначе письма подтверждения будут вести на `localhost`.

## Проверки

```bash
# права доступа на живой базе: 72 проверки, 4 реальных аккаунта
SUPABASE_SERVICE_KEY=... ADMIN_PASSWORD=... node scripts/smoke.mjs

# интерфейс в браузере: вход → каталог → отправка сообщения
TEST_PASSWORD=... node scripts/ui-check.mjs
```

`smoke.mjs` сам за собой убирает: тестовые группы, диалоги, файлы и аккаунты удаляются в конце.
`ui-check.mjs` требует системных библиотек Chromium (`npx playwright install --with-deps chromium`).

Ключи: в репозитории и в коде лежит только публичный ключ. `service_role` и пароли передаются
через переменные окружения.

## База

Миграции применяются в Supabase по порядку:
`init_messenger` → `rpc_functions` → `allow_soft_delete` → `part2_profiles_storage_search` →
`part2_storage_policies` → `part2_preview_attachment` → `part3_reactions_pins_voice` →
`bonus_time_capsule`.

Часть 3 добавила: `messages.duration_ms / pinned_at / pinned_by`, таблицу `message_reactions`,
функции `toggle_reaction()`, `pin_message()`, `can_see_message()` и новый вид превью чата
в `list_conversations()`.

Бонус добавил: `messages.open_at`, вид сообщения `capsule`, таблицу `message_capsules`
с правилом «отдавать текст только после срока», функцию `send_capsule()` и триггер
`capsule_cleanup`, стирающий запечатанный текст вместе с удалённым сообщением.
Таблицы `conversations` и `conversation_members` добавлены в публикацию Realtime —
переименование группы и изменение состава теперь доходят до собеседника сразу.

## Что починено в бонусной части

| Было | Стало |
|---|---|
| ответ на голосовое/удалённое сообщение цитировался как «вложение» | цитата знает про тип: «🎤 Голосовое», «⏳ Капсула», «сообщение удалено» |
| `URL.createObjectURL` вызывался прямо в рендере — утечка памяти на каждый кадр | ссылка живёт в хуке и освобождается при смене файла |
| удаление сообщения не показывалось до ответа сервера, а при ошибке молчало | оптимистичное удаление с откатом и текстом ошибки |
| ошибка одного чата оставалась на экране при переходе в другой | состояние ошибки сбрасывается при смене чата |
| уход со страницы во время записи оставлял микрофон включённым | запись останавливается при размонтировании |
| `MediaRecorder` мог не ответить, и кнопка «Отправить» зависала | сторож на 2 с, обработка `onerror`, пустая запись отбрасывается |
| удалённые файлы оставались в бакете навсегда | файл стирается вместе с сообщением, при удалении группы — вся её папка |
| расширение файла из имени попадало в путь как есть | `safeExt()`: только латиница и цифры, максимум 12 символов |
| `onAuthStateChange` мог заблокировать клиент Supabase | профиль грузится отложенно, повторное событие с тем же id игнорируется |
| пачка сообщений дёргала список чатов по разу на каждое | события склеиваются, один запрос на 200 мс |
| множество показанных уведомлений росло без предела | список id ограничен 400 записями |
| переименование группы и исключение участника не доходили до собеседника | подписка на `conversations` и `conversation_members`; если чат исчез — возврат к списку |
| реакция падала без следа в консоль | ошибка показывается в чате |
