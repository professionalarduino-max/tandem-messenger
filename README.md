## ⚡ Коротко

Tandem — полноценный мессенджер без собственного сервера: фронтенд на React общается напрямую
с Supabase, а вся безопасность живёт в Postgres (Row Level Security + функции `security definer`).
Сообщения, реакции, переименования групп и статусы «печатает…» прилетают по WebSocket, файлы
лежат в приватном бакете со ссылками на час, приложение ставится на телефон как PWA и работает
офлайн-заглушкой при обрыве сети.

| | |
|---|---|
| 🌐 **Демо** | https://professionalarduino-max.github.io/tandem-messenger/ |
| 🧱 **Стек** | React 19 · TypeScript · Vite 8 · Tailwind 4 · Supabase |
| 🔒 **Безопасность** | RLS на каждой таблице и на хранилище, 84 автопроверки прав на живой базе |
| 📦 **Размер** | ~156 КБ gzip, одна страница, без бэкенд-сервера |

## ⏳ Капсула времени — фишка проекта

> Сообщение, которое **физически невозможно** прочитать раньше срока. Такого нет ни в Telegram,
> ни в WhatsApp.

```
┌──────────────────────────────────────────┐
│  ⏳  Капсула времени                     │
│      откроется 25 ноября, 18:30          │
│      осталось 3 дня 4 ч                  │
└──────────────────────────────────────────┘
```

- кнопка ⏳ рядом со скрепкой: текст + срок (через час / завтра / через неделю / через год /
  свой момент) — и капсула уходит в чат;
- в ленте видно только карточку с обратным отсчётом; когда таймер доходит до нуля, текст
  появляется сам, без перезагрузки страницы;
- **главное:** текст лежит не в сообщении, а в отдельной таблице `message_capsules`, и правило
  доступа отдаёт его только при `open_at <= now()`. Ни devtools, ни прямой запрос к API, ни даже
  главный админ не достанут его раньше времени. Автор своё письмо видит всегда — прятать его
  от самого себя бессмысленно;
- удалили сообщение — запечатанный текст стирается триггером вместе с ним;
- в списке чатов и в уведомлении капсула подписана как «Капсула времени» с иконкой песочных
  часов, спойлера нет.

<details>
<summary>Как это устроено в базе</summary>

```sql
create policy capsule_read on public.message_capsules for select using (
  public.can_see_message(message_id)
  and (open_at <= now() or created_by = auth.uid())
);
```

Отправка идёт через `send_capsule()` (`security definer`): проверяет доступ к чату, непустой текст
до 4000 символов и срок от 30 секунд до 5 лет, затем создаёт сообщение вида `capsule` и запечатанную
строку рядом. Проверка `capsule_body_is_sealed` не даёт положить текст капсулы в саму таблицу
сообщений даже случайно.

</details>

## 👥 Каталог людей и админ-панель

**Вкладка «Люди»** — это не поиск по подстроке, а полный список всех, кто пользуется мессенджером.
Первыми идут те, кто сейчас в сети, у каждого видно имя, юзернейм, время последнего визита,
число сообщений и метка главного админа. Клик — и открывается личный чат (а на себе — настройки).
Данные отдаёт функция `list_users(q)`, поиск по тому же списку работает по имени и юзернейму.

**Админ-панель** (`/admin`, иконка графика в шапке) видна только главному админу и собирает
живую сводку по всему сервису:

| Блок | Что показывает |
|---|---|
| Главные цифры | пользователи и кто в сети, сообщения за сегодня, чаты, объём вложений |
| График за 14 дней | сколько сообщений писали каждый день |
| Люди | всего, онлайн, заходили за сутки и за неделю, новые за неделю |
| Что пишут | текст, файлы, голосовые, капсулы, реакции, закреплённые, правки, удаления |
| Капсулы времени | сколько запечатано, сколько уже открыто, ближайшее вскрытие |
| Самые активные | топ-8 людей с полоской активности |
| Живые группы | топ-6 групп по сообщениям, клик ведёт в чат |
| Новые пользователи | пятеро последних, кто зарегистрировался |

Цифры считает сама база: одна функция `admin_stats()` возвращает готовый JSON и начинается
с проверки `is_super(auth.uid())` — без прав она отвечает ошибкой, а не пустым объектом.
Клиент ничего не агрегирует и не обходит RLS; панель обновляется раз в минуту и по кнопке.

## 🔐 Права доступа

| Кто | Что может |
|---|---|
| Любой вошедший | видит **все группы** в каталоге и **всех людей** во вкладке «Люди», читает группы, вступает одним кликом, пишет, реагирует |
| Участник личного чата | только свой диалог; посторонние не читают, не пишут, не реагируют, не скачивают вложения |
| Админ группы | состав, роли, название, описание, аватарка, закреплённые, удаление сообщений и группы |
| **Главный админ** | админ **в каждой** группе автоматически, включая чужие и будущие; модерация везде; **админ-панель со статистикой** |

Главный админ определяется по почте в функции `super_admin_email()` и флагу `profiles.is_super_admin`.
Триггеры `setup_new_conversation` и `sync_super_admin` держат это состояние в актуальном виде:
создаётся новая группа — главный админ уже в ней с ролью `admin`.

Хранилище защищено теми же правилами: путь `avatars/users/{id}` пишет только владелец,
`avatars/groups/{id}` — админ группы, `attachments/{conversation_id}` — участник чата
(для открытых групп — любой вошедший).

## 🛠 Запуск локально

```bash
git clone https://github.com/professionalarduino-max/tandem-messenger.git
cd tandem-messenger
npm install
cp .env.example .env.local   # вписать URL проекта и публичный anon-ключ
npm run dev                  # дев-сервер, http://localhost:5173
```

Service worker в дев-режиме намеренно отключён (мешал бы горячей перезагрузке). Чтобы проверить
установку приложения и офлайн-режим, нужна собранная версия:

```bash
npm run build
npm run preview              # порт 4173, здесь работает PWA
```

Своя база поднимается миграциями из раздела [База данных](#-база-данных) — Supabase → SQL Editor,
по порядку.

## 🚀 Деплой

Проект собирается в статику, поэтому подходит любой хостинг фронтенда.

### GitHub Pages (используется сейчас)

Всё уже настроено: пуш в `main` запускает `.github/workflows/pages.yml`, который собирает проект
с `BASE_PATH=/tandem-messenger/`, кладёт копию `index.html` в `404.html` (SPA-маршруты вроде
`/c/<id>` иначе давали бы 404) и публикует `dist/`.

Чтобы развернуть у себя:

1. **Settings → Pages → Source: GitHub Actions**;
2. при другом имени репозитория поправить `BASE_PATH` в `pages.yml` (для `user.github.io` — `/`);
3. ключи проекта — **Settings → Secrets and variables → Actions → Variables**:
   `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

### Vercel

```bash
npm i -g vercel
vercel link        # выбрать аккаунт и проект
vercel --prod      # сборка и выкладка
```

`vercel.json` уже содержит сборку (`npm run build` → `dist`), SPA-перенаправление на `index.html`
и заголовки кеширования: service worker не кешируется, хешированная статика — на год.

### Переменные окружения

| Имя | Значение |
|---|---|
| `VITE_SUPABASE_URL` | `https://<ваш-проект>.supabase.co` |
| `VITE_SUPABASE_ANON_KEY` | публичный anon-ключ |
| `BASE_PATH` | только для Pages: подпапка сайта, например `/tandem-messenger/` |

Если переменные не заданы, приложение возьмёт публичные значения по умолчанию из
`src/lib/supabase.ts`. Секретный `service_role` в деплой не попадает — он нужен только скриптам
в `scripts/`.

После первого деплоя добавьте адрес сайта в **Supabase → Authentication → URL Configuration**
(Site URL и Redirect URLs), иначе письма подтверждения будут вести на `localhost`.

## ✅ Проверки

```bash
# права доступа на живой базе: 84 проверки, 4 реальных аккаунта
SUPABASE_SERVICE_KEY=... ADMIN_PASSWORD=... node scripts/smoke.mjs

# интерфейс в браузере: вход → каталог → отправка сообщения
TEST_PASSWORD=... node scripts/ui-check.mjs

# каталог людей, админ-панель и иконки: 16 проверок
TEST_PASSWORD=... node scripts/admin-check.mjs

# опубликованная версия: базовый путь, service worker, манифест, прямые ссылки
node scripts/pages-check.mjs [адрес]
```

Последняя проверка на боевом адресе — 11 из 11: страница открывается, вход отрисован, ассеты
и манифест ведут в подпапку, service worker зарегистрирован на `/tandem-messenger/`, Supabase
отвечает с этого домена, прямая ссылка на чат поднимает приложение, консоль чистая.

`smoke.mjs` сам за собой убирает: тестовые группы, диалоги, файлы и аккаунты удаляются в конце.
`ui-check.mjs` требует системных библиотек Chromium (`npx playwright install --with-deps chromium`).

Ключи: в репозитории и в коде лежит только публичный ключ. `service_role` и пароли передаются
через переменные окружения.

## 🗄 База данных

Миграции применяются в Supabase по порядку:

`init_messenger` → `rpc_functions` → `allow_soft_delete` → `part2_profiles_storage_search` →
`part2_storage_policies` → `part2_preview_attachment` → `part3_reactions_pins_voice` →
`bonus_time_capsule` → `directory_and_admin_stats` → `preview_kind_for_icons`.

| Миграция | Что добавляет |
|---|---|
| `init_messenger`, `rpc_functions` | профили, чаты, участники, сообщения, RLS, главный админ |
| `part2_*` | аватарки и бакеты, вложения, ответы, редактирование, полнотекстовый поиск |
| `part3_reactions_pins_voice` | `message_reactions`, `toggle_reaction()`, `pin_message()`, `can_see_message()`, `duration_ms`, закрепы |
| `bonus_time_capsule` | вид сообщения `capsule`, `messages.open_at`, таблица `message_capsules`, `send_capsule()`, триггер `capsule_cleanup` |
| `directory_and_admin_stats` | `list_users(q)` — весь каталог людей, `admin_stats()` — сводка для главного админа, превью чатов без эмодзи |
| `preview_kind_for_icons` | `list_conversations()` отдаёт `last_message_kind`, чтобы список чатов рисовал иконку типа сообщения |

Таблицы `conversations` и `conversation_members` добавлены в публикацию Realtime — переименование
группы и изменение состава доходят до собеседника сразу.

## 🩹 Что починено в бонусной части

| Было | Стало |
|---|---|
| ответ на голосовое/удалённое сообщение цитировался как «вложение» | цитата знает про тип: «Голосовое», «Капсула времени», «сообщение удалено» — с иконкой |
| `URL.createObjectURL` вызывался прямо в рендере — утечка памяти на каждый кадр | ссылка живёт в хуке и освобождается при смене файла |
| удаление сообщения не показывалось до ответа сервера, а при ошибке молчало | оптимистичное удаление с откатом и текстом ошибки |
| ошибка одного чата оставалась на экране при переходе в другой | состояние ошибки сбрасывается при смене чата |
| уход со страницы во время записи оставлял микрофон включённым | запись останавливается при размонтировании |
| `MediaRecorder` мог не ответить, и кнопка «Отправить» зависала | сторож на 2 с, обработка `onerror`, пустая запись отбрасывается |
| удалённые файлы оставались в бакете навсегда | файл стирается вместе с сообщением, при удалении группы — вся её папка |
| расширение файла из имени попадало в путь как есть | `safeExt()`: только латиница и цифры, максимум 12 символов |
| `onAuthStateChange` мог заблокировать клиент Supabase | профиль грузится отложенно, повторное событие с тем же id игнорируется |
| пачка сообщений дёргала список чатов по разу на каждое | события склеиваются, один запрос на 200 мс |
| множество показанных уведомлений росло без предела | список id ограничен 400 записями |
| переименование группы и исключение участника не доходили до собеседника | подписка на `conversations` и `conversation_members`; если чат исчез — возврат к списку |
| реакция падала без следа в консоль | ошибка показывается в чате |
